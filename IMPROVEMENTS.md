## 六、实施顺序（已完成）

实际执行顺序与结果：

1. **第一批（P0-3、P0-4、P0-5、P0-6、P0-1）**：限流 key、`ADMIN_TOKEN` 去默认值、`DATA_TTL` 夹紧、
   重定向白名单、随机接口 `no-store` —— 均为单点改动，已随回归测试一起完成。
2. **第二批（P1-2、P1-7）**：合并按 id 去重、`DATA_SOURCES` 非法降级。
3. **第三批（P1-1、P1-3、P1-4、P1-5、P1-6）**：single-flight + 重试、内容哈希 ETag、
   清单来源 SSRF 防护、健康检查 `state`、热缓存不再掩盖 failures。
4. **第四批（P1-9 + P2-1）**：新增 `store` / `config` / `hardening` / `compat` / `data` 五个测试文件，
   引入 ESLint + Prettier 并接入 CI。
5. **第五批（P2-2 ~ P2-7 + 第五节杂项）**：采样率、 stricter tsconfig、CI 类型生成、
   宽松限流、数据校验脚本、Hitokoto 兼容层、仓库卫生与文档同步。

> 每次变更后均执行 `npm run typecheck && npm test`，P0/P1 项已同步补对应测试用例。

> 每批完成后建议跑 `npm run typecheck && npm test`，P0/P1 项需同步补对应测试用例。
